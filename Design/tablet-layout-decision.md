# 태블릿 가로 레이아웃 구현 방식 결정

- 날짜: 2026-10-11
- 결정: **방법A — 기존 컴포넌트 + 반응형 CSS 미디어쿼리** (`mockup/responsive-css` 목업 기반, 사용자 브라우저 비교 후 선택)

## 배경

웹 UI 이중 비율 대응(모바일 세로 현행 유지 + 태블릿 가로 ≥1024px)을 위해 두 방식을
대표 2화면(홈·관리자 대시보드)에만 적용한 실행 목업으로 병렬 비교했다.

- **방법A** `mockup/responsive-css` (커밋 80ed063): 4파일 +178/−18 — app.css의
  `@media (min-width: 1024px)` 블록 1곳에 집중, 전환은 순수 CSS(플리커 없음),
  기존 모바일 규칙 무수정, 사이드 내비도 `AuthorizeView` 안이라 로그인 정책 일치
- **방법B** `mockup/separate-layout` (커밋 248e7c4): 8파일 +331/−70 —
  `TabletLayout.razor` 물리 분리 + matchMedia JS interop 셸 스왑, prerender 시
  모바일 폴백 플래시, 미로그인 화면에도 사이드 내비 노출(모의 목업 잔여 이슈)

## 근거

1. 두 방식 모두 페이지 콘텐츠 조정에는 CSS가 필요하다(방법B 워커 확인:
   "CSS가 없어지는 게 아니라 파일로 이동") — B의 이점은 셸 분리뿐인데 유지
   포인트는 js+컴포넌트+css로 3개 늘어난다.
2. B의 유일한 고유 이점(C# 레벨 폭 분기 `isTablet`)은 현재 요구에 없다(AGENTS.md §1 YAGNI).
3. A가 변경 규모(178 vs 331줄)·회귀 위험(기존 규칙 무수정)·전환 품질(플리커 없음)에서 우위.

## 파기

- 방법B 목업 브랜치(`mockup/separate-layout`)는 비교 근거로 보존하되 채택하지 않는다.
