# 고핑 홈 → MY 승인 기록

## 조사와 기준

기준 커밋: `59724bdf6591bda36a01cbf333e2f44380dd0187`.
조사: [high-ping-navigation-investigation.md](high-ping-navigation-investigation.md).
읽기 전용 동일 배포 이미지 복제본에서 잘못된 임시값·통계 카드 추가에 따른 달력 재배치·순차 API 지연 누적을 관측했다. 사용자 제공 재현 기준은 iPhone 15 Pro / iOS 26.6.1 / LTE / Tailscale Funnel이다. 통제된 타임라인은 desktop Edge이며 실기기 최종 확인은 별도로 받는다.

## 승인 1 — 무엇을 문제로 해결할지

본 세션 `ask_user_question`, header `문제 판단 승인`에서 조사/캡처를 설명한 뒤 질문했다:

> 조사 결과를 기준으로, 이번에 해결할 문제를 무엇으로 확정할까요? 해결 방법은 이 답변 후 별도로 승인받겠습니다.

사용자 응답 원문:

> 임시값·화면 밀림 둘 다 (Recommended)

이 선택의 설명:

> 잘못된 기본값 노출과 데이터 도착 후 본문 재배치를 해결 대상으로 확인합니다. 순차 호출로 노출 시간이 길어지는 점도 함께 고려합니다.

**승인됨:** 미로딩 데이터를 정상값처럼 보여주는 화면과 불필요한 본문 재배치를 개선 대상으로 삼는다. 이는 특정 구현 방법이나 제품 코드 수정 승인이 아니다.

## 승인 2 — 해결 방향

본 세션 `ask_user_question`, header `해결 방향 승인`에서 후보의 장단점을 설명한 뒤 별도로 질문했다:

> 어떤 해결 방향으로 수정할까요?

사용자 응답 원문:

> 대기 표시·공간 유지 + 병렬 호출 (Recommended)

승인된 설명:

> 기본값 대신 명시적인 로딩 표현을 보여주고 통계·달력 공간을 유지합니다. 독립 API를 동시에 읽어 지연 누적도 줄입니다. 기존 API·인증·업무 규칙은 그대로 둡니다.

같은 도구의 `실기기 기준` 질문에 대한 사용자 응답 원문:

> 1. Iphone 15 pro, 26.6.1, lte, 배포 상태는 funnel을 통해

**승인됨:** MY 로딩 표현·공간 유지와 기존 profile/stats/calendar 읽기 병렬화. 새 API/캐시·인증/업무/DB 규칙 변경은 하지 않는다. 실제 개선폭은 수정 후 측정한다.

## 추가 승인 — 보안 패치

Docker 재검증에서 기존 `Microsoft.AspNetCore.Components.WebAssembly.Server 10.0.12`의 NU1903 경고를 발견했다. 2026-10-13 공개된 [CVE-2026-102870](https://github.com/advisories/GHSA-g27p-qf6j-c96c)와 [CVE-2026-96230](https://github.com/advisories/GHSA-qjpx-jqm5-h2c4)의 영향 범위는 10.0.0~10.0.12, 패치는 10.0.13이다. 공식 설명의 위험 조건은 WASM 디버깅/개발 서버 디버그 경로이며 현재 Program은 `UseWebAssemblyDebugging`을 켜지 않는다. 그렇다고 패키지 영향 범위 자체를 무시하지 않았다.

범위 확장 여부를 `ask_user_question`, header `배포 전 보안`에서 별도로 질문했다. 사용자 응답 원문:

> 보안 패치도 포함 (Recommended)

승인 범위: **WebAssembly.Server 10.0.12 → 10.0.13만 변경**, .NET 10 유지, 새 기능/업무 규칙 없이 빌드·테스트·Docker 회귀 재검증 후 Web만 반영. 다른 패키지를 임의로 일괄 업데이트하지 않는다.

## 수정·반영 게이트

- 승인 2 답변까지 제품 코드/기존 테스트 스크립트 변경은 없었다. 진단은 `.diag`/`artifacts`, 조사·승인 기록만 `docs`에 생성한 상태에서 두 승인을 받았다. 이후 승인 범위의 구현/검증을 시작한다.
- 본 세션의 `Proceed`는 조사 계속 요청이며 해결 방향 승인으로 간주하지 않는다.
- 두 승인을 모두 기록하기 전 제품 코드를 수정하거나 운영 Web를 반영하지 않는다.
- 변경 후에는 승인 범위와 실제 diff, 정상/고지연 회귀, 실제 배포 자산, 실기기 최종 확인을 기록한다. 새로운 모듈/공개 계약이 필요해지는 경우 프로젝트의 신선 컨텍스트 리뷰 게이트를 추가한다.
